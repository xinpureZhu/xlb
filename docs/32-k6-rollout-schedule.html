07风险、回滚与穿透点 排期本身的风险是「批次被打散」与「漏插版本族」

1交人批次被打散

集群/平台动作若逐项临时插队，会反复冻结环境。对策：归并到周二 / 周四两批，周五只验收不改动；每批前先跑一次 preview.sh / replay 预检。

2版本族漏插

B4 只改一个流程会静默漏掉 redeploy / quality / hotfix 族。对策：按 §8 的插入点清单逐文件核对，验收时逐文件确认节点已出现。

3门禁噪声化

环境不稳导致频繁误红，团队开始忽略门禁——这是最可能的失败模式。对策：D2 先告警期 2 个迭代；一次重试 + 隔离清单 + 先跑 env-gate。

风险的穿透点会被哪一步击穿逐项回滚动作
把门禁开放给集群内任意进程（误借审批节点做自动通过）B4 试图改审批节点语义不采用；自动判定只走自建 smoke-run 节点，审批保持人工
写脏数据 / 触发下游 MQ 与风控A1 写接口脚本在 prod 被误跑writePath: true 的套件 envs 不含 prod；prod 只跑只读探活
共享环境互扰B3 开关一次性全开逐服务灰度；同环境同时间只跑一个套件（Lease 串行）
假绿（脚本跑通但什么都没测）A4 通道未验通却依赖「空数据判红」通道未通前以退出码为主信号，并把该降级登记为技术债
凭据散落A2 模板把账号写进 300 个服务仓只走集群 Secret + envFrom；脚本只读 __ENV

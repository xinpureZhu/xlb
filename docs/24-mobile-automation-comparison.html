01结论与判据 Appium = 命令翻译器 + 会话托管；与 Agent 路线在「谁决定下一步」上完全相反

图 1 · Appium 宿主侧分层：Express → 路由 → 伞驱动 → 独立 driver 包 → 设备组件

1启动链（全部在一个进程内）

index.js → AppiumInitializer.init()：解析 CLI/配置文件 → loadExtensions 读 APPIUM_HOME/extensions.yaml → 初始化 logsink → new AppiumDriver(args) → preflightChecks()（Node 版本硬校验 + schema 校验）→ AppiumMainRunner.run()：加载 driver/plugin 类 → buildServerOpts → 起 HTTP/WS → 可选注册 Selenium Grid → 挂 SIGINT/SIGTERM → 打印监听 URL。

配置优先级：CLI/程序化 args > 配置文件（lilconfig，支持 package.json 的 appiumConfig 字段）> schema 默认值。

2协议：新会话强制 W3C

路由表是 6 张表的合并：W3C_ROUTES → JSONWP_ROUTES → MJSONWP_ROUTES → APPIUM_ROUTES → APPIUM_DEVICE_ROUTES → EXTENSION_ROUTES（后者覆盖前者）。免 session 命令白名单只有 createSession/getStatus/getAppiumSessions。

非 W3C 结构的 caps 直接抛 SessionNotCreatedError；旧 JSONWP/MJSONWP 路由仍注册但全部标记 deprecated，首次命中打一次警告后照常执行。错误模型同时携带三套标识：数字 JSONWP code、W3C 字符串 error、HTTP 状态码。

3扩展模型：driver 就是 npm 包

package.json 里的元数据字段是 appium.driverName / appium.pluginName（不是 appium.driver），driver 还必须有 automationName/platformNames/mainClass。安装 appium driver install uiautomator2 会走 npm 装进 APPIUM_HOME/node_modules、写入 manifest（schema rev 4），并做 peerDependencies.appium 远程版本门禁。

加载策略：默认加载全部已装 driver，plugin 默认一个都不加载（--use-plugins all 才全开）；单个扩展加载失败只记错误并跳过，不阻断服务启动；driver 类可注入 newMethodMap/updateServer 来扩展服务端能力。

4会话与安全边界

sessionId 由 driver 生成（uuidV4），伞驱动只维护 sessions 等三张表；同一会话内命令由 per-instance AsyncLock 串行（日志会打印「Scheduling the … command to the commands queue」），跨会话天然并发。本体没有设备池/调度器——并行隔离靠 driver 侧端口参数与 --session-override。

默认绑 0.0.0.0:4723、base-path 默认空（Appium 2 起废弃 /wd/hub）、--allow-cors 默认关（打开即打印安全警告）、--relaxed-security 只影响「服务端下发给 driver 的不安全特性」且被 --deny-insecure 覆盖；官方立场是自建内网、不要暴露公网。

AUiAutomator2（黑盒、跨应用）

能操作任意 App，符合真实用户路径；定位走 AccessibilityNodeInfo 树；支持 UiScrollable 滚动定位。官方已警告 Google 计划移除 UiSelector/UiScrollable 家族，届时 -android uiautomator 定位会失效。

适用：端到端回归、跨 App 流程、第三方 App。

BEspresso（进程内、灰盒）

适用：自家 App 内部白盒校验；不能跨 App。

1Android 动作注入：坐标手势，不是 UiObject2.click()

真实链路是 BaseElement.click() → AxNodeInfoHelper.click() → GestureController，后者通过反射调用 androidx.test.uiautomator.GestureController.performGesture(PointerGesture…)：click 是一次 pause(0) 的按下抬起，longClick 是 pause(LongPressTimeout)，scroll/fling 注入后还会用 UiDevice.performActionAndWait 等滚动结束事件；手势区域按 0.1 比例内缩以避免边缘误触。

常规点击不走 adb shell input（那只出现在 mobile: 便捷包装里，如 mobile: pressKey）。文本输入是与点击分离的 ElementHelpers.setText()，hideKeyboard 靠切换自定义输入法（io.appium.settings 的 AppiumIME/UnicodeIME）。

06等待与防抖 idle + quiescence 是确定性的核心 · 动画禁用靠反射改 animationScales

平台参数（默认值）机制
Android UIA2 SettingswaitForIdleTimeout = 10000ms所有核心 uiautomator 对象在查找前先等空闲；Click handler 点击后还会显式 Device.waitForIdle()；设 ≤0 表示跳过
waitForSelectorTimeout = 10000ms仅对 -android uiautomator 策略生效
actionAcknowledgmentTimeout = 3000ms · scrollAcknowledgmentTimeout = 200ms等动作对应的 AccessibilityEvent / 滚动回执

wdaEventloopIdleDelay = 0 · animationCoolOffTimeout = 2s前者延迟 setEventLoopHasIdled:（flaky 时官方建议从 ≥3s 起试）；后者在每个改变状态的动作后等动画结束
snapshotMaxDepth = 50（上限 62）· accessibilityDeadline = 0快照深度；后者给无障碍快照设上限、防 WDA 永久挂死（官方建议只在风险步骤前后临时开）
关键纠偏（写脚本/写文档都容易错）：Android 的动画禁用不是改 settings put global window_animation_scale 这类全局设置。真实实现是两条：API ≥ 26 由 instrumentation 参数 --no-window-animation 完成；API < 26 由 io.appium.settings 反射拿到 android.view.IWindowManager，把 getAnimationScales() 返回的浮点数组整体填 0（会话结束再填 1），权限是 SET_ANIMATION_SCALE。Espresso 侧默认即开启动画禁用。

隐式/显式等待的分工：显式等待完全属于客户端库行为，driver 不参与；隐式等待在两端实现不同——iOS 是 driver 侧 implicitWaitForCondition 轮询重发查找请求；Android 由宿主处理 W3C timeouts，另有服务端内建的 idle 等待与 waitForSelectorTimeout。Espresso 提供第三种形态：IdlingResource，阻塞式等 UI 线程空闲（mobile: registerIdlingResources，类必须有静态 getInstance()）。

Android：元素在但找不到加显式等待；排查拼写；xpath 场景调 allowInvisibleElements/ignoreUnimportantViews/snapshotMaxDepth 等（官方同时警告这些会显著拖慢）
iOS：应用慢或交互超时应用必须 idle 且动画结束才能交互；调 waitForIdleTimeout/animationCoolOffTimeout/wdaEventloopIdleDelay；主线程死循环的 App 基本不可自动化
iOS：WDA 永久挂死 / 命令莫名多等 60saccessibilityDeadline 临时开启；后者是 testmanagerd 崩溃重启所致，需终止目标 App 或重启设备
iOS：真机不稳、系统弹窗点不到真机官方明说「特别 flakey」，必要时重启设备；弹窗用 autoAcceptAlerts/autoDismissAlerts/mobile: alert；iOS 18 的有限通讯录弹窗需单独指定 active app

1并行：端口族 + 单进程多会话

Android 每会话隔离 systemPort（8200–8299）、chromedriverPort、mjpegServerPort；iOS 隔离 udid、wdaLocalPort（8100 起）、mjpegServerPort（9100）、derivedDataPath。两种拓扑：per-process（每会话一个 server）与 per-request（一个 server 多会话，靠 caps 指定设备）。

2默认超时矩阵（排障先看这四个）

instrumentation 安装 20s（uiautomator2ServerInstallTimeout）· 服务端拉起 30s（uiautomator2ServerLaunchTimeout）· 请求读超时 240s（uiautomator2ServerReadTimeout）· 会话空转 newCommandTimeout 60s（超时即强杀会话）。

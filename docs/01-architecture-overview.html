01整体分层 五层 · 端只连 BFF

系统自上而下分为五层，端应用只与 BFF 交互，BFF 聚合业务中台与高性能 Rust 服务，中台之间以 HTTP（SOA/Feign/HttpExchange）+ 消息（RocketMQ/Kafka/RabbitMQ）解耦。

05多租户「货道」模型 主线 / wanchi / wanquan / wancan

GitOps 中大量业务域按租户复制为并行命名空间（lane），实现多品牌/多租户隔离部署，代码同源、配置与镜像分支隔离：

主线 (goods / retail / marketing / member-center) 万橙 wanchi (retail-wanchi / marketing-wanchi / goods-wanchi ...) 万群 wanquan (retail-wanquan / goods-wanquan / oms-wanquan ...) 万餐 wancan

例如商品域在 goods/、goods-wanchi/、goods-wanquan/ 三条货道各自部署 goods-b / pc-bff / 各类同步消费者。租户差异通过 Jsonnet 的 getEnvSpecificValue 与 per-lane artifacts.libsonnet 镜像分支控制。

06鉴权与权限模型 iAuth 为权限中枢 · auth-server 只管 Token

  • iAuth 是权限中枢（外部服务）：身份 = user-id 头 + Bearer JWT；租户 = company_id；门店范围 = storeId / userStoresQuery[] + admin 标志；权限 = {app_type, path, action} 元组，经 POST /internal.authority.check[.batch] 校验（见 cms-server）。
  • auth-server 不是 RBAC，而是第三方平台 Token 代理：统一获取/缓存/刷新 微信 MP+公众号、支付宝、快手、抖音、美团点评、乐檬(nhsoft) 的 access token / 签名，供全体 BFF 共享。
  • C 端 xlb-mp-bff 以会员 JWT 鉴权，叠加踢出（kick-out）、状态黑名单、同盾风控与灰度金丝雀。
安全提示 xlb-mp-bff/积分下单安全加固方案.md 记录了 /order/point/* 的 4 项漏洞（member_id 未与 JWT 交叉校验、company_id 可篡改致越权、支付组合校验缺失、活动类型可篡改）及 P0/P1 修复方案，属需持续关注的安全项。

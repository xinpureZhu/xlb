Critical 概览（7 项）
  1. 鉴权可被绕过：@IgnoreToken 会短路 @Server 校验，导致门店零售价批量增删改端点完全无鉴权，且 companyId 取自请求体 → 跨租户任意写。
  2. 服务间共享 Token 硬编码在 5+ 处源码，持有它即可让所有权限检查无条件通过；另内嵌一枚有效期到 2099 年的 JWT。
  3. 生产 JWT RSA 私钥、OSS AK/SK、短信 apikey、飞书 webhook 明文入库。
  4. 结算分布式锁在真正扣款前就释放 → 并发重复支付；反结账完全无锁 → 重复退款。
  5. 排序字段直接拼进原生 SQL → SQL 注入（6 处 DAO 可达）。
  6. 诺诺发票回调无签名校验 → 可伪造开票状态并批量回写订单。
  7. Java 8 + Spring Boot 2.7 双 EOL，且依赖 guava 20.0(2016)、pdfbox RC 版上生产、fastjson AutoType 作 Redis 序列化器。

1.1 四路持久化的后果

同一实体既可能经 EntityManager 一级缓存写入（BaseDao.update → merge），也可能被 @Modifying JPQL 或原生 SQL 绕过缓存直接改库，持久化上下文与数据库状态可能不一致。CustomPageDaoV2 的 setupQuery 有反射白名单校验，说明团队知道该做校验，但同类的 find()/findByTable() 与全部原生 SQL 路径都没有。

4.2 插件机制

三类插件（促销 PromotionPolicyPlugin / 券 CouponPlugin / 支付 SettlementPayPlugin）均继承 Spring Plugin 的 Plugin<D>，由 RetailApplication.registerPlugins() 在 @PostConstruct 时用 getBeansOfType 扫描注册进 static final HashMap。

PluginRegistry 是残缺实现 三个 registry 除 registerPlugin()/getRequiredPluginFor() 外，其余 15+ 个接口方法全是假实现：countPlugins() 返回 0、contains()/hasPluginFor() 返回 false、getPlugins() 返回空列表、iterator() 直接返回 null；CouponPluginRegistry.getPluginFor() 恒返回 Optional.empty()。任何按接口契约使用这些方法的代码都会静默失效或 NPE。
plugin/registry/PromotionPluginRegistry.java:27,90-114 · CouponPluginRegistry.java:42-44

另外 static final HashMap 作为注册表在启动后被写入——虽然当前只在 @PostConstruct 单线程写一次，但缺少不可变封装与启动期完整性校验。

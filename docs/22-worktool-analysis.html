01定位与版本状态 无障碍 RPA 机器人 · 开源版冻结于 v2.8.1

worktool 是一个依附企业微信（com.tencent.wework）运行的无人值守群管理机器人：用 Android 官方 AccessibilityService 模拟真人操作企微 UI，后端通过 WebSocket 下发指令驱动。无 hook、无 root、无内存修改，纯无障碍 API + 手势注入。

图 2 · 一条远程指令的完整执行时序

  • 连接：URL = {host}/webserver/wework/{robotId}（Constant.kt:124），心跳 5s、断线 5s 重连（WebSocketManager.java:33-34）；onOpen 即广播跳转企微首页待命（WeworkService.kt:135）。
  • 解密：encryptType=1 时 AES/CBC/PKCS7 解密指令体（MyLooper.kt:91-103）；密钥与 IV 硬编码在客户端（见 §6 S1）。
  • 三级去重：messageId 30s 确认表（WebSocketManager.java:64-78）→ LinkedHashSet 批内去重 → 同特征值 removeMessages 丢弃未执行的重复指令（MyLooper.kt:104-118）。
  • 串行执行：所有 UI 自动化在单一 Handler 线程跑（MyLooper.kt:26-58）；悬浮窗暂停时忙等（:33-36）。
  • 自愈：执行异常先 goHome() 再重试一次，仍失败回报 ERROR_ILLEGAL_OPERATION（:38-51）；进程级崩溃由 GlobalException 全局 handler 重启。
  • 队列控制指令：ROBOT_QUEUE_CLEAR 清空全部待执行指令；每条指令执行完自动补一条 LOOP_RECEIVE_NEW_MESSAGE 回到收消息主循环（:107-132）。

05UI 自动化核心与消息抓取 sleep 驱动同步 · 节点树主动遍历 · 图片走文件系统旁路

1AccessibilityUtil（1354 行）

三类能力：查询（按类名/文本/描述找节点、前后兄弟、可滚动集合）、全局操作（回退/回桌面）、窗口操作（点击/长按/滚动/SET_TEXT 输入/坐标手势）。全部阻塞式，约定只在子线程调用；同步靠 150/500/800ms 三档 sleep 轮询。

2mainLoop 收消息（WeworkLoopImpl）

循环体：不在首页则先抓当前房间消息 → 回首页 → 扫会话列表红点进房抓消息 → 处理通讯录好友请求 → 实名/risk 门禁检查 → sleep 300ms 再来一轮。崩溃后自动重新入队主循环指令。

3图片旁路（MultiFileObserver）

直接 FileObserver 监听企微私有目录 .../com.tencent.wework/files/imagecache/imagemsg2（WeworkService.kt:78），新图即经 HttpUtil.pushImage 上报。Android 10+ 依赖 manifest 的 requestLegacyExternalStorage 续命，Android 11+ 该路径实际已不可达 —— 开源版图片能力的隐性断点。

4无障碍能力声明

accessibility_service_config.xml：typeAllMask 全事件 + flagRetrieveInteractiveWindows + flagIncludeNotImportantViews + canPerformGestures，packageNames 限定企微。notificationTimeout 100ms，事件粒度拉满。

版本敏感的根源：所有节点查找按文本/类名硬匹配企微 UI 文案（如「通讯录」「可能的同事」），Constant.AVAILABLE_VERSION 硬编码支持列表止于 4.1.10。sleep 轮询 + 文案匹配的组合决定了它对企微改版零容忍 —— 这是商业版持续适配的护城河，也是开源版必然过期的原因。

08结论与二开建议 工程完成度高的无障碍 RPA 框架 · 安全模型几乎为零

worktool 开源版是一个完成度很高的无障碍 RPA 框架：指令队列、去重、自愈、分层都做对了，39 分支指令目录覆盖企微群运营的全部高频动作。但安全模型几乎为零（§6），且开源版已冻结、对企微新版必然失效。
